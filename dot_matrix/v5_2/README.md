What started as an experiment to try out the new Rust-oxide compiler in CUDA Toolkit 13.4.2 has turned into a full refactoring of the tensor core engine v5.1 into rust. Along the way bugs in CUDA Fortran v5.1 were fixed (overflow and underflow in particular) so that a v5.2 of the CUDA Fortran tensor core engine is also included. Further optimisations in the Rust version of the tensor core engine are likely to overcome the remaining performance deficits compared to Fortran. The bottom line is that the Rust version going forward may well supplant the CUDA Fortran version despite CUDA Rust's beta status.

One of the biggest surprises was that a comprehensive Claude Fable 5.1 code review did not pick up the bugs fixed in v5.2: that was only done after reviewing performance metrics from the CUDA Fortran vs CUDA Rust benchmarks (which in turn led to a rabbit hole of bug fixes). There have been a number of projects now that have benefited from a dual track (Fortran and Rust for example). Claude may miss a bug in one language but when you have two versions in different languages, errors can be detected more easily.
